# Patrol Radar Pro — Open Testing release gate

Android package: io.github.missionaryj.patrolradar. Subscription product: patrol_radar_pro, base plan: monthly, U.S. price: $1.99/month. **Open Testing only. Never production.**

## Code delivered
- Native Google Play Billing Library 9.1.0 product lookup, monthly purchase, restore and pending-state callbacks.
- Supabase-authenticated server calling Google's purchases.subscriptionsv2.get API before unlocking Pro. Server stores purchase tokens privately with RLS, acknowledges after fulfillment, and applies expiry and state policy.
- Google Cloud Pub/Sub real-time developer notifications (RTDN), with authenticated OIDC push and Google re-verification, for renewals, cancellations and refunds.
- Effective Pro on Android = a Play-release install-date founder (firstInstallTime before 2026-11-16T19:54:00-06:00, and only when the installed build is not debuggable and the installer is `com.android.vending`) OR server-verified Pro OR, while the verifier is unreachable, the last server-verified status cached on the device (founder: permanent; Play: until Google expiry + 3 days). Debug and sideloaded builds ignore `pr.foundingTester` and the install time. The web build never grants Pro (src/entitlement/proAccess.ts).
- The app still posts install time and the checkout account hash to `founder-install`, but the server records a grant only when the Edge Function secret `FOUNDER_AUTO_CLAIM` is `on`, `true`, `1`, or `yes`. Unset means off. The one-time code box is the path for a real founding tester.
- Reinstall recovery for subscribers: checkout sets `setObfuscatedAccountId` to SHA-256 of a salt + the per-app ANDROID_ID. When a token is already owned by another anonymous user, the server moves it to the caller only if Google's `externalAccountIdentifiers.obfuscatedExternalAccountId` equals the hash the caller presents (`relink_pro_purchase`, compare-and-set). Otherwise the app shows a clear "linked to a different install" message (HTTP 409).
- Billing uses its own auth session (`pr.pro.auth`), separate from City Chat (`pr.chat.auth`).
- Free Stop History preview; verified users get full shading and filters. Web has no Play checkout.

## Founding testers: grandfather migration and trust tradeoff
- A Play-release install from before the cutoff keeps the on-device founder unlock across updates of that same install. Debug and sideloaded builds do not. The server grant is off by default, so a reinstall does not recover founder Pro unless you redeem a one-time code (or you deliberately set `FOUNDER_AUTO_CLAIM`).
- Trust: `firstInstallTime` is self-reported. With auto-claim left unset, calling `founder-install` does not insert a `pro_founders` row. Set `FOUNDER_AUTO_CLAIM=on` only if you accept that a forged time before the cutoff can create a grant. `pro_founders.source` and `first_install_at` still record any row that is created. TODO: require a Play Integrity verdict (MEETS_DEVICE_INTEGRITY, PLAY_RECOGNIZED) in claimFounderInstall once the Integrity API is enabled.
- A new phone (different ANDROID_ID) needs a one-time code: generate 24 or more random characters, store only SHA-256 in `pro_founder_codes`, and send the code privately. Factory reset also changes ANDROID_ID. That code path is the manual allowlist.
- Do not expect `founder-install` to return foundingTester true while auto-claim is off. Confirm a code redemption instead.

## Limitations and security
- A copied genuine Play purchase token cannot move a purchase to another account unless the thief also presents the victim phone's account hash (SHA-256 of an app-scoped ANDROID_ID only readable by Patrol Radar on that phone). Purchases made on a different phone, or before setObfuscatedAccountId shipped, cannot be relinked automatically: use support with the Google Play order number.
- The device caches the last verified status (`pr.pro.verified`) so paying users keep Pro offline; a server "not Pro" answer clears it. The server honors rows verified in the last 3 days (was 30 minutes) when Google is unreachable; RTDN revocations still remove access immediately.
- A purchase token is not a purchase until server-validated. Refund/revocation and expired subscriptions remove access. A paid cancellation typically keeps access until verified expiry.
- The heatmap source files under public/data/stop-heat are publicly downloadable; this gate protects in-app enhanced features, not confidential data files. Do not market them as exclusive secret datasets.
- Never ship Pro checkout with unavailable backend or unprovisioned founding grants. Never publish to production.
